<objective>
Replace all remaining PostgREST FK joins on the `users` table with separate `user_profiles` view queries and manual data assembly, closing the gap identified in 04-VERIFICATION.md.

Purpose: After the RLS migration (04-02) tightened the users table SELECT policy to owner-only, PostgREST FK joins like `user:users(id, name, email)` return null for other-user rows. This causes group member names, lender/borrower names, notification sender names, and item owner names to silently disappear from the UI. The security goal (RLS-02) is met -- no email/phone is exposed -- but this functionality regression must be fixed.

Output: All 4 affected server action files updated to use `user_profiles` view queries instead of FK joins; UI components updated to stop referencing email from these queries.
</objective>

**Pattern to follow (already established in `getActiveBorrowsGroupedByContact` in `app/borrow/actions.ts` lines 260-341 where contacts are fetched separately and assembled):**

```typescript
// 1. Remove FK join from select
// 2. Collect user IDs
const userIds = [...new Set(results.map(r => r.some_user_id).filter(Boolean))]
// 3. Batch fetch from user_profiles
let usersMap: Record<string, { id: string; name: string }> = {}
if (userIds.length > 0) {
  const { data: profiles } = await supabase
    .from('user_profiles')
    .select('id, name')
    .in('id', userIds)
  if (profiles) {
    usersMap = Object.fromEntries(profiles.map(p => [p.id, p]))
  }
}
// 4. Attach to results
return results.map(r => ({
  ...r,
  someUser: usersMap[r.some_user_id] || { id: r.some_user_id, name: 'Unknown' }
}))
```
