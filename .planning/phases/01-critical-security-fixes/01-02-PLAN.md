Audit and fix all console statements in server action files. Apply these rules:

**Rule 1 -- Remove all console.log statements entirely:**
- `app/items/actions.ts:39` -- `console.log('Creating item:', {...})` -- REMOVE (leaks user.id)

**Rule 2 -- Remove console.error statements that precede a return with the error message:**
When the pattern is `console.error(...); return { error: error.message }`, the error message is already returned to the caller. The console.error is redundant and leaks internal details. Remove the console.error line, keep the return.

Apply to ALL instances in these files:
- `app/items/actions.ts`: lines 21, 56, 108, 137, 157, 301
- `app/auth/actions.ts`: line 69 (logs full error object -- REMOVE)
- `app/contacts/actions.ts`: lines 28, 62 (use JSON.stringify -- REMOVE), lines 97, 144, 177, 214, 271, 366
- `app/borrow/actions.ts`: lines 205, 216, 274, 318 (uses JSON.stringify -- REMOVE), 425, 445, 524, 573, 596, 607, 628, 689, 709
- `app/groups/actions.ts`: lines 72, 268, 295, 340
- `app/notifications/actions.ts`: lines 60, 83, 106, 132, 173, 197, 220, 245
- `app/users/actions.ts`: line 51

**Important:** Do NOT add a logging framework or replacement logging mechanism. The error information is already propagated via return values. Simple removal is the correct approach for this phase.

**Important:** Do NOT modify function logic, return values, or control flow. Only remove/modify console statements. Each function should continue to return the same values it currently returns.

**Important:** For console.error statements in notification-creation blocks that say "Don't fail the request if notification fails" -- remove the console.error but keep the comment and the non-failing behavior pattern.
