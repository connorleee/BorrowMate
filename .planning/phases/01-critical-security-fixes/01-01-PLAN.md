<task type="auto">
  <name>Task 1: Fix middleware auth guard with public route allowlist</name>
  <files>utils/supabase/middleware.ts</files>
  <action>
Replace the broken conditional block (lines 49-61) in the `updateSession` function with an explicit public route allowlist.

The current bug: `!request.nextUrl.pathname.startsWith('/')` is always false because every pathname starts with `/`. This means the redirect block never executes.

Replace with:

```typescript
const publicRoutes = ['/', '/auth', '/about']
const isPublicRoute = publicRoutes.some(
    route => request.nextUrl.pathname === route ||
             request.nextUrl.pathname.startsWith(route + '/')
)

if (!user && !isPublicRoute) {
    const url = request.nextUrl.clone()
    url.pathname = '/auth'
    return NextResponse.redirect(url)
}
```

This covers:
- `/` (landing page) -- exact match
- `/auth` and `/auth/callback` -- prefix match via startsWith('/auth/')
- `/about` -- exact match

Everything else (dashboard, items, contacts, groups, borrow, discover, users, notifications) requires authentication.

Remove the old commented-out lines about "Landing page is public?" -- the intent is now explicit in the allowlist.

Do NOT change the middleware matcher config in `middleware.ts` (root file) -- that controls which routes middleware runs on and is correctly configured. Only change the auth logic in `utils/supabase/middleware.ts`.
  </action>
